3. Handling pauses, emotions, and non-verbals
This is the core pain point you called out. I’d handle it in three layers:

3.1 Text-level markup → engine-specific prompts
Create your own tiny markup / attribute system instead of relying on (pause) etc., which you’ve already seen fail.

For example, let scripts contain tags like:

[pause:500]

[breath:soft]

[laugh:short]

[emotion:excited], [style:whisper]

Your Rust pipeline:

Strip tags from the text sent to the engine (so you don’t hear “pause” or the literal tag).

Convert them into:

Explicit silence insertion in the timeline.

Prompt hints, especially for Parler:

"[emotion:excited]" → “Mike’s voice, excited and energetic but still clear, very close microphone, very clear audio…”
GitHub
+1

For engines that support punctuation-driven prosody (Parler, XTTS, many TTS models), optionally add commas and full stops in strategic places (Parler explicitly recommends commas for prosody control).
GitHub

You keep the script language engine-agnostic, and encode engine specifics in adapter code.

3.2 Timeline-level silence (post-processing)
Don’t rely on the engine’s idea of a “comma-sized” pause; make pauses deterministic:

After each segment’s TTS result arrives, your audio pipeline:

Appends pause_before_ms worth of silence,

Appends the TTS audio,

Appends pause_after_ms worth of silence.

You can generate silence as arrays of zeros at the target sample rate:

fn silence_samples(duration_ms: u32, sample_rate: u32) -> Vec<i16> {
    let total_samples = (duration_ms as u64 * sample_rate as u64 / 1000) as usize;
    vec![0i16; total_samples]
}
For podcasts, this gives you:

Precisely staggered turn-taking (no awkward overlaps),

Exact control over “radio-style” pacing: long dramatic pauses, fast back-and-forth, etc.

// components/tts-spec/tts-spec-script/src/validate.rs
use std::collections::HashSet;
use tts_spec_model::{Script, ScriptError, SegmentId};

pub fn validate(script: &Script) -> Result<(), ScriptError> {
    validate_segment_ids_unique(script)?;
    validate_sample_rate(script)?;
    Ok(())
}

fn validate_segment_ids_unique(script: &Script) -> Result<(), ScriptError> {
    let mut seen: HashSet<&str> = HashSet::new();
    for seg in &script.segments {
        let id: &str = &seg.id.0;
        if !seen.insert(id) {
            return Err(ScriptError::Validation(format!("Duplicate segment id: {id}")));
        }
    }
    Ok(())
}

fn validate_sample_rate(script: &Script) -> Result<(), ScriptError> {
    if script.sample_rate == 0 {
        return Err(ScriptError::Validation("sample_rate must be > 0".into()));
    }
    Ok(())
}

// 4th function reserved for future rule

use tts_spec_model::Script;
use crate::events::{TimelineEvent, TimelineEventKind};

pub fn build_timeline(script: &Script) -> Vec<TimelineEvent> {
    let mut events = Vec::new();
    let mut current_ms: u64 = 0;

    for (idx, seg) in script.segments.iter().enumerate() {
        push_pause(&mut events, &mut current_ms, idx as u32, seg.pause_before_ms);
        push_segment(&mut events, &mut current_ms, idx as u32, seg.id.0.clone());
        push_pause(&mut events, &mut current_ms, idx as u32, seg.pause_after_ms);
    }

    events
}

fn push_pause(events: &mut Vec<TimelineEvent>, current_ms: &mut u64, idx: u32, duration_ms: u32) {
    if duration_ms == 0 {
        return;
    }
    let event = TimelineEvent {
        order_index: idx,
        at_ms: *current_ms,
        kind: TimelineEventKind::Silence { duration_ms },
    };
    *current_ms += duration_ms as u64;
    events.push(event);
}

fn push_segment(
    events: &mut Vec<TimelineEvent>,
    current_ms: &mut u64,
    idx: u32,
    id: String,
) {
    let event = TimelineEvent {
        order_index: idx,
        at_ms: *current_ms,
        kind: TimelineEventKind::TtsSegment { segment_id: SegmentId(id) },
    };
    events.push(event);
    // actual audio duration is unknown here; will be resolved later
}

pub fn estimate_duration_ms(events: &[TimelineEvent]) -> u64 {
    events
        .iter()
        .filter_map(|e| match &e.kind {
            TimelineEventKind::Silence { duration_ms } => Some(*duration_ms as u64),
            _ => None,
        })
        .sum()
}

pub fn concat_i16(buffers: &[Vec<i16>]) -> Vec<i16> {
    let total: usize = buffers.iter().map(|b| b.len()).sum();
    let mut out = Vec::with_capacity(total);

use hound::{WavWriter, WavReader, WavSpec, SampleFormat};
use std::path::Path;
use std::fs::File;
use std::io::BufWriter;

pub fn write_i16_mono<P: AsRef<Path>>(
    path: P,
    samples: &[i16],
    sample_rate: u32,
) -> Result<(), Box<dyn std::error::Error>> {
    let spec = WavSpec {
        channels: 1,
        sample_rate,
        bits_per_sample: 16,
        sample_format: SampleFormat::Int,
    };
    let writer = WavWriter::create(path, spec)?;
    write_samples_i16(writer, samples)
}

fn write_samples_i16(
    mut writer: WavWriter<BufWriter<File>>,
    samples: &[i16],
) -> Result<(), Box<dyn std::error::Error>> {
    for s in samples {
        writer.write_sample(*s)?;
    }
    writer.finalize()?;
    Ok(())
}

pub fn read_i16_mono<P: AsRef<Path>>(
    path: P,
) -> Result<(u32, Vec<i16>), Box<dyn std::error::Error>> {
    let mut reader = WavReader::open(path)?;
    let spec = reader.spec();
    let samples: Result<Vec<i16>, _> = reader.samples::<i16>().collect();
    Ok((spec.sample_rate, samples?))
}

// 4th reserved for stereo or floats later
pub fn write_i16_stereo<P: AsRef<Path>>(
    path: P,
    samples: &[i16],
    sample_rate: u32,
) -> Result<(), Box<dyn std::error::Error>> {
    // similar to mono
    write_i16_mono(path, samples, sample_rate)
}

pub async fn render_to_wav<P: AsRef<Path>>(
    client: &AllTalkClient,
    state: &PipelineState<'_>,
    out_path: P,
) -> Result<(), ScriptError> {
    let mut buffers: Vec<Vec<i16>> = Vec::new();

    for seg in &state.script.segments {
        push_segment_with_pauses(client, &mut buffers, state.sample_rate, seg).await?;
    }

    let final_buf = concat_i16(&buffers);
    write_i16_mono(out_path, &final_buf, state.sample_rate)
        .map_err(|e| ScriptError::Parse(e.to_string()))
}

    }

    Ok(())
}

6. How this maps to your goals
Small units:

Modules are narrow and mostly pure.

Functions per module ≤ 4.

Crates per component ≤ 4.

Strict layering:

tts-spec-* knows nothing about HTTP, AllTalk, or audio I/O.

tts-engine-* knows nothing about WAV layout; only “segment → WAV bytes”.

tts-render-* knows nothing about YAML / CLI; only Script + AllTalkClient → buffers → WAV.

tts-apps is thin glue and UX.

Pure vs state-changing:

Modules like parse.rs, validate.rs, silence.rs, concat.rs, build.rs, mapping.rs are pure.

Modules like http_ops.rs, wav_io.rs, exec.rs, handlers.rs are side-effecting and clearly separated.

Easy testing:

Unit tests live beside each module or in /tests per crate.

Integration tests can be in a separate component (e.g. components/tts-tests/) that spins up a test AllTalk instance and runs end-to-end scripts.

If you’d like, next step we can zoom into one component at a time (e.g. tts-spec) and fully flesh out the real Cargo.tomls and initial skeleton files so you can cargo new the whole hierarchy with a single shell script and start filling in implementations incrementally.
